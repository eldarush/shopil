# Experimental constrained answers (not enabled by default)

`python -m chat ... --structured` and `python -m integration.run ... --structured`
use an experimental Actor that selects typed references to calculated evidence
fields, or declares the requested information unavailable. It cannot author
numbers, dates, provenance labels, or arbitrary narrative. A deterministic
renderer resolves each reference against the frozen source row and shows the
field value together with that row's identifiers, source metric/units, explicit
half-open range, and actual snapshot capture time. The existing real Critic then
reviews exactly this rendered candidate; rejection triggers the usual maximum
three-attempt loop. Only approved candidates enter history.

Successful Actor outputs are preserved as `actor_output_json` alongside the
rendered `draft` in attempt audits, with
`rendering="deterministic_fact_references"`. The rendered prose must not be
represented as text generated by the language model.

This guarantees rendering fidelity, NOT semantic correctness. The Actor may
select the wrong product/metric or incorrectly declare data unavailable, and a
weak Critic may still approve it. Selected product3 values will be labeled
product3, not silently relabeled product5. Arbitrary number-membership checks or
correct provenance footers do not fix incorrect factual prose; this mode avoids
that prose entirely. Supported fields are the explicit calculated-metric catalog;
review-text interpretation, general explanations and suggested alternatives are
not implemented. This is a material capability restriction and requires rubric
review and actual-model evaluation before choosing it for the assignment.

No free-form answer is silently rewritten. Unknown references, conflicting status,
extra JSON fields, duplicate references and schema violations fail closed.
Mocked regression tests prove reference/rendering mechanics, not model accuracy.
